## Summary
[[coretext]] was reframed away from being a gatekeeper tool that forces the agent to query an external index. The stronger direction is to let the agent keep access to native files and tools, while Coretext runs in the background as a relevance engine.

The discussion separated three layers. [[GitNexus]] or similar code graph tools should own code intelligence. [[Language Server Protocol]] can help with precise symbol navigation and maintenance, but it does not replace a repo-scale graph. Coretext should own project knowledge in markdown, especially specs, decisions, and long-term associative memory.

The markdown graph remains simple: `contains`, `parent_of`, and `references`. Links from markdown to code should default to file-level, with optional symbol-level anchors only for high-value cases. This avoids drift from renames and refactors.

[[SurrealDB]] should not be the source of truth. It should act as a reproducible embedded index and query engine. Markdown and code files remain the semantic truth. [[Git]] remains the temporal truth. [[Hebbian Learning|Hebbian experience]] should come from a separate canonical event store such as JSON, NDJSON, or SQLite, with SurrealDB holding only materialized weights for serving.

The old approach of upserting full node content into SurrealDB and removing the agent's access to markdown files was rejected. The stronger model is subconscious recall: Coretext injects compact cues such as heading name, path, and a short reason, then the agent uses native search, file reads, grep, or future LSP navigation to inspect the content. This matches how CLI agents actually behave and avoids making Coretext compete with native agentic search.
