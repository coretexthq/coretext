## Summary
Explored the architectural shift of Coretext towards a "Headless OS" and Agentic Inter-Process Communication (IPC). Analyzed the distinction between stateless payloads (like MCP context dumps or URL search parameters) and stateful pointers (like CLI flags or SurrealDB node IDs). Evaluated the role of Agent Skills (via YAML frontmatter) combined with CLI tools as a lighter, progressive-disclosure alternative to heavy MCP servers. Critiqued the comparison between lean, headless agent workflows and traditional corporate tools (Jira, Slack), acknowledging the necessity of heavy UI for human organizational psychology while keeping the backend ruthless and file-first. Concluded that the human brain's serial language output is the current bottleneck, validating the shift from optimizing personal motor friction (via Warp/Raycast) to optimizing agent autonomy via stateful pointers.

## Problems & Solutions
- **Problem**: Chaining stateless shell commands (`git push && gemini...`) leads to fragile pipelines lacking error recovery.
  - **Solution**: Shift to a pointer-driven architecture using Coretext's graph (SurrealDB) as a state machine. Pass node IDs (e.g., `--node=story-123`) as triggers, allowing agents to selectively hydrate context via Progressive Disclosure.
- **Problem**: MCP servers often cause context window overflow by treating interactions as stateless payload dumps.
  - **Solution**: Combine CLI tools (for deterministic execution) with Agent Skills (Markdown with YAML frontmatter) for Just-in-Time Learning, replacing heavy custom MCP servers with lightweight, progressive pointers.
- **Problem**: Traditional corporate tools (Jira, Slack) are stateless and inefficient compared to a file-first graph knowledge base.
  - **Solution**: Decouple the head. Maintain Coretext as the purely headless, stateful kernel (backend) for agents, while keeping tools like Slack as the necessary, read-only view layer (frontend) to satisfy human organizational psychology and visibility needs.
- **Problem**: Optimizing terminal setups and motor workflows has hit diminishing returns because the human limits of serial language output have been reached.
  - **Solution**: Pivot from being a "Commander" optimizing personal keystrokes to a "Director." Build Coretext so the machine maintains the state graph, reducing necessary human input from exhaustive prompts to simple, context-rich pointers.
