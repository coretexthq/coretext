## Summary
Discussed the evolution of the Coretext architecture, abandoning the biological "Hebbian" metaphor (probabilistic weights, "feeling" intuition) in favor of a mathematically rigorous Operating System metaphor (Deterministic State-Driven Development or D-SDD). The architecture uses a Planner (Kernel) to orchestrate tasks, an Executor (User Process) to write code, and a Reviewer (Quality Gate) to audit. Instead of fuzzy weights, the system uses `experience.json` as a telemetry audit log to explicitly update dependencies in a SurrealDB graph (the MMU/Page Table). The Coretext daemon uses this graph to passively inject precise contextual routing hints (laws) to cold-booted subagents, bridging the gap between rigid frameworks (like OpenSpec and Superpowers) and bare-metal agentic execution.

## Highlights
- **Sequential Commits**: The Executor and Reviewer subagents share the same dedicated Git worktree and branch, making sequential commits to avoid branch proliferation. The Planner orchestrates them from the `main` branch.
- **Agent Capabilities**: The Planner agent is given internet access and `activate_skill` to research and compile instructions. The Reviewer agent is given file editing tools to fix minor issues immediately.
- **Project-Level Agents**: The `planner`, `executor`, and `reviewer` agents are formally defined in `.gemini/agents/*.md`, keeping their specific instructions isolated and modular, while sharing the `AGENTS.md` core directives.
- **Personal Assistant vs. Autonomous Factory**: D-SDD is an asynchronous, deterministic factory for software. A Personal Assistant (Exocortex) should be synchronous and exploratory, using Obsidian's `[[wikilinks]]` for native progressive disclosure instead of a rigid SurrealDB graph.
- **SurrealDB as MMU vs. Multimodal Database**: SurrealDB should be stripped down to a Deterministic Context Router (MMU) mapping `[File] -> REQUIRES -> [Constraint]`. Multimodal intent (like linking a UI mockup image) belongs natively in the Markdown `target_state.md`, not indexed in the database.
- **Serverless Cloud Adaptation**: The D-SDD architecture maps perfectly to cloud/serverless workflows. In a cloud PR setup, the "Council" of Reviewer agents should be read-only (commenting on PRs) to avoid merge conflicts, while the Executor synthesizes fixes based on the Planner/Human's ultimate tie-breaking directive.
- **Framework Agnosticism**: Coretext v2 (D-SDD) is the permanent Data/State layer. Heavy execution harnesses (like OmO or Superpowers) are ephemeral and can be hot-swapped to write the code today, while the D-SDD graph ensures the system remains future-proof for tomorrow's smarter models.

## Problems & Solutions
- **Problem**: Relying on "Hebbian decay" and "passive injection" of intuition allows obsolete architectural patterns to persist (Semantic Rot) and creates a positive feedback loop of errors (Hallucination Gap).
  - **Solution**: Shift to an Operating System metaphor. Treat subagents as volatile processes that boot cold. Treat the Planner as the Kernel that manages explicit state updates. Use `experience.json` as a telemetry log to establish deterministic, hard-coded dependency edges in SurrealDB rather than fuzzy weights.
- **Problem**: Updating specifications *after* execution (Ex Post Facto Development) allows rogue subagents to permanently mutate architecture without global awareness, violating constraints.
  - **Solution**: Enforce the Causal Arrow of Engineering (Intent -> Execution). If an Executor hits an architectural constraint, it must halt, write to `dev.md` (Hardware Interrupt), and let the globally-aware Planner amend the laws (`ARCHITECTURE.md`) *before* respawning the Executor.
- **Problem**: 10 agents writing 10 lessons a day into a shared "intuition" graph creates "Multi-Agent Entropy" and conflicting cognitive crossfire for future agents.
  - **Solution**: Subagents do not mutate the graph. They only generate telemetry in `experience.json`. The Planner agent periodically reviews the telemetry to synthesize explicit, deterministic rules and updates the graph centrally.
- **Problem**: A Planner agent reviewing a large Git diff suffers from context window degradation and loses sight of the high-level PRD.
  - **Solution**: Introduce a dedicated Review Subagent that boots cold in an isolated Git worktree, reads the PRD and Diff, and nitpicks the code. It summarizes the implementation in a concise `dev.md` file, which the Planner then reads to make high-level merging and architecture update decisions.
- **Problem**: Using Vector Search (Semantic RAG) on monolithic specifications causes "Topological Blindness" where global architectural constraints are missed because they are semantically equidistant from specific feature queries.
  - **Solution**: Ensure global laws (`ARCHITECTURE.md`) are *always* present in the Executor's context window, bypassing the need for fuzzy search entirely for global constraints.
- **Problem**: Monolithic "Agile Slop" (like massive `epics.md` and `prd.md` files) causes "Context Overload" and "Hierarchical Tunnel Vision," making agents miss cross-document requirements.
  - **Solution**: Break requirements into modular `docs/`. The Planner generates ephemeral, hyper-focused `target_state.md` and `atomic_step.md` files for the Executor. The SurrealDB MMU passively injects exact cross-reference hints based on telemetry, delivering Just-In-Time (JIT) context.
- **Problem**: Heavy execution harnesses (BMad, OmO) become bureaucratic bloat as foundational models gain superior long-chain reasoning.
  - **Solution**: Adopt Framework Agnosticism. Use Coretext v2 (D-SDD) as the permanent data/state layer. Treat heavy harnesses as ephemeral, hot-swappable tools used to write code *today*, ensuring the architecture remains future-proof for *tomorrow's* smarter models without needing a rewrite to remove legacy lifecycle hooks.
