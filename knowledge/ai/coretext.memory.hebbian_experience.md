### Evolution of the Architecture
The architecture evolved through three distinct phases:
1.  **Infrastructure Heavyweight:** The initial approach relied on complex external cognitive architecture ([[coretext]], [[multimodal]] [[Hybrid Search]], [[SurrealDB]], [[RAG]]). This treated the LLM as a calculator requiring heavy data pipelines and metadata taxes (e.g., forced YAML frontmatter).
2.  **Custom JSON Graph (Digital [[Hippocampus]]):** The design pivoted to simplifying databases into a lightweight JSON AST for an agent to traverse. However, forcing an agent to learn a custom JSON traversal tool contradicted its native pre-training, essentially reinventing the filesystem. The architecture was on the verge of being abandoned due to the rigid nature of using a JSON DAG for workflow orchestration.
3.  **Native Primitives (The Breakthrough):** The realization that the filesystem *is* the graph saved the architecture. By dropping the rigid JSON workflow, the system returned to native primitives: [[AGENTS.md]] (rules), `@` imports (directed edges/strong dependencies), and `wikilinks` (undirected edges/weak dependencies). JSON was then brilliantly repurposed from a workflow dictator into an implicit telemetry observer ([[experience.json]]), completing the "[[Everything is a file]]" vision without sacrificing biological-style intuition.

The pivot to native primitives was largely driven by the evolution of AI tooling. When designing Coretext initially, tools lacked simple `@` file-based context injection, and LLM [[Agentic Search]] was not capable enough to traverse links autonomously. Today, researching [[Gemini CLI]] and [[Claude Code]] [[Memory]] systems reveals that modern models are powerful enough to make heavy index/query engines like Coretext + [[SurrealDB]] unnecessary overhead. While Coretext retains a niche for specialized multimodal hybrid search, its original role as a general knowledge indexer relies on too many redundant parts that are better handled by native file formats and LLM intuition.


### Key Breakthroughs
- **Distillation to Bare-Metal Primitives:** The architecture was refined to three core components:
  1.  **[[Markdown]] ([[Semantic Memory]]):** Human and machine-readable text files for knowledge, `AGENTS.md` (general instructions), and Agent Skills (procedural knowledge).
  2.  **[[Git]] ([[Temporal]]):** Provides an immutable timeline, isolation (worktrees), and the absolute source of truth (the "Atomic Time" of the company).
  3.  **[[JSON]] (Topological/Hebbian):** Repurposed from a rigid workflow state machine into a dynamic map of experience.
  4. [[Agent Skills]] ([[Procedure Memory]])
- **Rejection of the Workflow State Machine:** A master `workflow.json` or rigid MCP orchestration acts as restrictive bureaucracy and limits LLM reasoning. Instead, routing is context-driven via "[[Progressive Disclosure]] Context Injection": `AGENTS.md` sets the rules, `@` imports dynamically pull in specific procedural skills, and `[[wikilinks]]` act as weak dependencies for autonomous discovery.
- **The "Everything is a File" Philosophy:** By unifying workflows around `AGENTS.md` and plain-text skills, the system bypasses heavy API endpoints and JSON-RPC servers (which suffer from token bloat). It relies on tools the LLM already natively understands (grep, git, file reading), mapping perfectly to Plan 9 OS concepts.
- **[[Hebbian Learning]] via `experience.json`:** Rather than forcing agents to pay a "Metadata Tax" (writing [[YAML frontmatter]] or explicit "Related Notes"), the architecture shifts to **Implicit Telemetry**. A [[Git hook]] (acting like [[Linux]] `strace` or a Prefetch daemon) observes actual tool calls (e.g., `read_file`, `activate_skill`) during a session and writes the historical correlations into an `experience.json` file. 
- **Dynamic Topology vs. Static Parsing:** This approach replaces the heavy parsing and upserting required by previous iterations (like Coretext mapping to SurrealDB). The `experience.json` captures what *actually fired together* in the agent's context window, allowing for biological-style synaptic weight updates that prime future agent intuition without forcing rigid workflows.
