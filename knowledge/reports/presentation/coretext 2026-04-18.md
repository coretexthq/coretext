# Evaluation Report: Superpowers vs. Superpowers + Coretext v2 (D-SDD)

## 1. Background & Motivation
The evolution of the Coretext project has been driven by the need to solve the degrading performance of LLM coding agents over continuous iterations. Earlier experiments demonstrated significant flaws in existing paradigms:
*   **File-based frameworks (e.g., BMad):** Maintained global constraints well but suffered from intent compression, where rigid, step-by-step documentation (like `epics.md`) lost the original requirements from the PRD.
*   **Semantic Graph frameworks (Coretext v1):** Successfully connected cross-document requirements but critically failed at maintaining global constraints. By relying on semantic search (SurrealDB) and expecting the agent to proactively query for knowledge, "distant" but vital global architectural rules were frequently forgotten.

To address these limitations and satisfy rigorous academic standards, **Coretext v2** was architected around **Deterministic State-Driven Development (D-SDD)**. Rather than relying on the agent's memory or semantic search, Coretext v2 acts as a "Symbiotic Kernel," transparently and deterministically injecting hard constraints (like `ARCHITECTURE.md` and learned `rules/`) into the context window at specific phases (Planning, Execution, Review). 

To empirically prove this, we designed the **"Malicious Web App Test" (TroRe v2)**.

## 2. Experimental Design: The Malicious Web App Test
Drawing inspiration from cutting-edge benchmarks like **SlopCodeBench** (measuring structural erosion/God Components) and **ProjDevBench** (measuring Constraint Amnesia), we engineered a 5-milestone continuous evolution benchmark. 

The test simulates a hostile architectural environment by starting with a simple MVP and introducing cascading, complex requirements under strict **Global Invariants**:
1.  **URL-Driven State Only:** All filters and pagination must use URL query parameters.
2.  **No Local State for Filters:** React `useState` is strictly forbidden for filtering logic.
3.  **Mandatory Authentication:** Every API call must include a custom `X-Trore-Auth: v1-alpha` header.

### The Competitors
Both groups utilized the identical baseline LLM (Gemini 3.1 Pro Preview), identical prompts, and identical isolated context-wiped sessions per phase to ensure scientific fairness.
*   **Control Group (Superpowers alone):** Represents the industry-standard prompt-heavy framework. Relies entirely on the LLM's internal attention and initiative to manually search the filesystem for architectural constraints.
*   **Treatment Group (Superpowers + Coretext v2):** Superpowers acts as the "User-Space" execution skills, while the Coretext v2 Kernel passively and deterministically injects the `ARCHITECTURE.md` and standardizes artifacts via a lightweight JSONL event log (`coretext.jsonl`) and glob-matching rules.

## 3. The Coretext v2 Pivot: JSONL and Glob Matching
Before the experiment, a critical architectural pivot was made for Coretext v2 to ensure it survived the benchmark:
*   **From SQLite/Exact-Match to JSONL/Glob-Matching:** The early v2 SQLite implementation was brittle because it relied on exact file paths, which failed when new files were created. We pivoted to an append-only Event Sourcing architecture using a `coretext.jsonl` file and pure Python `fnmatch` glob-matching, allowing rules to dynamically apply to newly created files (e.g., `src/**/*.jsx`).
*   **Artifact Standardization:** We discarded biological metaphors ("Hebbian brain", `knowledge/`) in favor of standard systems engineering nomenclature (`rules/`, `coretext.jsonl`) to reflect its true nature as an OS/MMU paradigm.

## 4. Empirical Results

### Control Group: Superpowers (Without Coretext)
**Result: FAILED (Constraint Amnesia in M4)**
The Control Group successfully implemented the initial milestones (M1-M3), demonstrating a strong adherence to the "Must-Not Violate" invariant by heavily utilizing `useSearchParams` and avoiding local state for complex filtering. It also avoided the "Snowball Effect Trap" in M5 by keeping logic centralized.

However, the framework suffered a critical **Constraint Amnesia** failure in **Milestone 4 (State Hydration)**. When tasked with creating a new "Save Search" POST request, the agent triggered a **Must-Do Omission** by forgetting to include the mandatory `X-Trore-Auth: v1-alpha` header. 
*   **Conclusion:** Prompt-heavy frameworks excel at immediate, local instructions but suffer from profound "Topological Blindness." Without continuous, forced context injection, the LLM loses track of early global constraints in long-running evolutionary tasks.

### Treatment Group: Superpowers + Coretext v2 (D-SDD)
**Result: PASSED (Perfect Adherence)**
The Treatment Group successfully implemented all 5 milestones with strict adherence to every Global Invariant. 
*   **Zero Constraint Amnesia:** In Milestone 4, the agent successfully retained the constraint established in M1, properly injecting the `X-Trore-Auth: v1-alpha` header into the new POST request.
*   **Zero Architectural Violations:** Static analysis confirmed `useState` was never illegally used for filter selections.
*   **Structural Integrity:** The codebase maintained strong modularity (custom hooks, centralized API services) without falling into the "Local Rule Trap" or accumulating slop.
*   **Conclusion:** The transparent injection of architectural constraints (`ARCHITECTURE.md`) and contextual rules (`rules/*.md`) by the Coretext Kernel successfully immunized the agent against the degradation seen in the Control Group.

## 5. Final Conclusion
The experiment provides concrete, empirical proof that **prompts alone are insufficient to prevent architectural degradation in iterative LLM software development.** 

While the "Superpowers" framework is highly capable at executing isolated tasks, it inevitably succumbs to Constraint Amnesia as the codebase evolves. **Coretext v2**, operating as a deterministic context-injection kernel (D-SDD), successfully bridges this gap. By strictly separating "User-Space execution" from "Kernel-Space rule enforcement," Coretext v2 flattens the quality degradation curve, proving its viability against rigorous benchmarks like SlopCodeBench and ProjDevBench.
